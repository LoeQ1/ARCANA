# ARCANA 스토리 작성 안내

이 프로젝트의 대화와 분기는 JavaScript 코드가 아니라 JSON 데이터로 작성합니다. 엔진은 장면 그래프를 읽고, 선택 조건을 확인한 뒤, 선택 효과를 플레이어 상태에 적용합니다.

## 파일과 연결 구조

- 현재 실행되는 스토리 파일: `content/story/arrival.json`
- 아이템, 퀘스트, 지역의 ID와 설정: `content/data/gameplay.json`
- 분기와 효과를 실행하는 엔진: `game/story-engine.js`
- 스토리 그래프 및 게임 데이터 참조 검사: `tools/validate_story.py`

현재 앱은 시작할 스토리 파일 하나를 불러옵니다. 장면을 추가할 때는 우선 `arrival.json`의 `nodes` 안에 장면을 추가하고, 선택지의 `next`에 다음 장면 ID를 적습니다. `next`는 같은 파일의 장면으로 연결합니다. 별도의 스토리 파일을 추가하기만 해서는 앱에서 자동으로 불러오지 않습니다.

## 장면과 선택지

각 장면은 고유한 ID와 `title`, `text`, `conditions`, `choices`를 가집니다. 조건이 비어 있으면 항상 표시됩니다. 선택지는 `id`, 플레이어에게 보일 `text`, 선택 가능 조건인 `conditions`, 상태 변경 목록인 `effects`, 다음 장면인 `next`로 구성합니다.

```json
{
  "storyId": "arrival",
  "version": 1,
  "startNode": "village_notice",
  "nodes": {
    "village_notice": {
      "title": "마을 게시판",
      "text": "게시판에 새 의뢰가 붙어 있습니다.",
      "conditions": [],
      "choices": [
        {
          "id": "accept_request",
          "text": "의뢰를 맡는다",
          "conditions": [],
          "effects": [
            { "type": "startQuest", "questId": "ruins_clue" }
          ],
          "next": "request_accepted"
        }
      ]
    },
    "request_accepted": {
      "title": "의뢰 수락",
      "text": "숲에서 단서를 찾아오기로 했습니다.",
      "conditions": [],
      "choices": []
    }
  }
}
```

이 예시는 구조 설명용입니다. 실제 `arrival.json`을 고칠 때는 기존 장면과 선택지를 유지하면서 필요한 부분을 병합하세요.

## 게임 시스템과 연결하기

스토리 ID는 `gameplay.json`의 ID를 참조해야 합니다. 검증기는 다음 참조가 실제 데이터에 있는지 검사합니다.

| 목적 | 선택 조건 예시 | 선택 효과 예시 |
| --- | --- | --- |
| 퀘스트 | `{ "type": "questStatus", "questId": "ruins_clue", "status": "complete" }` | `{ "type": "startQuest", "questId": "ruins_clue" }` |
| 아이템 | `{ "type": "hasItem", "itemId": "torn_record" }` | `{ "type": "grantItem", "itemId": "torn_record", "quantity": 1 }` |
| 지역 | `{ "type": "locationIs", "location": "forest" }` | `{ "type": "unlockLocation", "location": "forest" }` |
| 진행 플래그 | `{ "type": "flagEquals", "key": "found_ruins_clue", "value": true }` | `{ "type": "setFlag", "key": "found_ruins_clue", "value": true }` |
| 성장 | `{ "type": "levelAtLeast", "value": 2 }` | `{ "type": "grantXp", "amount": 10 }`, `{ "type": "grantGold", "amount": 5 }` |

선택 조건은 전부 만족해야 선택지가 표시됩니다. 전투처럼 스토리 밖의 게임 행동이 퀘스트 상태나 플래그를 바꾸면, 플레이어가 `이야기`를 다시 열었을 때 그 상태에 맞는 선택지가 나타납니다. 이 방식으로 대화 선택과 탐험·전투·보상을 연결합니다.

전투 목표 퀘스트는 `gameplay.json` 퀘스트에 `objective`를 정의합니다. 예를 들어 `ruins_clue`는 `forest_wolf`를 `forest`에서 처치해야 진행됩니다. 엔진은 승리한 순간의 몬스터 ID와 플레이어 위치가 모두 목표와 일치할 때만 저장된 `questProgress`를 올리고, 요구 횟수에 도달하면 퀘스트를 완료합니다. 그래서 다른 지역에서 같은 몬스터를 처치해도 목표에 반영되지 않습니다.

현재 지원하는 조건은 `flagEquals`, `levelAtLeast`, `hasItem`, `questStatus`, `locationIs`입니다. 효과는 `setFlag`, `startQuest`, `advanceQuest`, `completeQuest`, `grantItem`, `removeItem`, `grantXp`, `grantGold`, `unlockLocation`, `changeRelation`입니다. 새 조건이나 효과가 필요하면 JSON에 임의의 JavaScript를 넣지 말고, 엔진과 두 검증기(브라우저·Python)에 같은 규칙을 추가해야 합니다.

## 작성 규칙

1. 장면 ID와 선택지 ID는 영문 소문자와 밑줄로 작성합니다. 플레이어에게 보이는 문장은 `title`, `text`, `choice.text`에 적습니다.
2. 모든 `next`는 `nodes` 안에 실제로 존재해야 합니다. 모든 장면은 시작 장면에서 도달 가능해야 합니다.
3. 퀘스트, 아이템, 지역을 참조할 때는 `gameplay.json`에 먼저 정의하고 같은 ID를 사용합니다.
4. 선택 효과는 선택이 확정될 때 한 번 적용됩니다. 보상 효과를 바꿀 때는 이미 선택한 캐릭터의 기록에도 영향을 줄지 검토합니다.
5. 배포한 선택지 ID와 장면 ID는 가급적 유지합니다. 저장 데이터의 스토리 이력과 보상 중복 방지에 사용됩니다.
6. 막다른 장면은 `choices: []`인 실제 장면으로 표현하고, 그 장면으로 `next`를 연결합니다. 선택지에서 `next`를 생략하면 스토리 진행 위치가 초기화됩니다.

## 확인 방법

스토리를 수정한 뒤 프로젝트 루트에서 다음 명령을 실행합니다.

```powershell
python tools/validate_story.py content/story/arrival.json
```

정상 데이터는 스토리 ID, 버전, 장면 수와 함께 `OK`로 표시됩니다. 잘못된 장면 연결, 도달할 수 없는 장면, 지원하지 않는 규칙, 없는 퀘스트·아이템·지역 ID는 오류로 표시됩니다. 로그인 후 게임 화면에서도 불러오는 스토리를 브라우저 검증기로 확인합니다.

## 시각 편집기

편집기는 로그인 후 게임 화면의 **편집기** 링크에서 엽니다. 설정된 편집자 이메일 계정에만 링크가 표시되며, 편집기 주소로 직접 들어와도 Supabase 로그인 세션과 이메일을 다시 확인합니다. 편집 권한은 현재 leekh375@naver.com으로 제한되어 있습니다. 이는 클라이언트의 간편 경로 제한이며, 편집 데이터 파일 자체에 대한 서버 권한 제어는 아닙니다.

프로젝트의 HTTP 서버를 실행한 뒤 `/editor/`를 엽니다. 기본으로 `arrival.json`과 게임 데이터를 불러오며, 장면은 카드로, 선택지는 화살표로 표시합니다. 카드를 선택해 제목·본문·표시 조건과 선택지의 조건·효과·다음 장면을 편집하고, 장면과 선택지를 추가할 수 있습니다. 편집기 상단의 **검증**은 그래프와 게임 데이터 ID 연결을 확인합니다.

스토리 설정 아래에는 퀘스트 목표 트리거도 표시됩니다. 스토리 선택지의 `startQuest`와 같은 퀘스트 ID를 기준으로 연결되며, 몬스터 처치 이벤트의 장소·대상·필요 횟수를 설정할 수 있습니다. 트리거를 수정하면 `gameplay.json`에도 저장해야 하므로 **저장**할 때 게임 데이터 파일 저장도 요청합니다.

편집기 위쪽의 **월드 맵** 탭에서는 `gameplay.json`의 지역과 출구 연결을 카드 지도에서 확인합니다. **지역 추가** 후 표시 이름, 설명, 명령어 별칭, 이동 출구, 탐험 허용, 조우 몬스터와 확률을 지정할 수 있습니다. 탐험 아이템 보상에서 발견 아이템과 발견 확률도 설정할 수 있으며, 발견에 실패하면 골드를 얻습니다. 게임 안에서는 지역 이름이나 별칭 또는 `이동 <지역 이름>`으로 이동하고, 탐험을 허용한 지역에서 `탐험` 명령을 사용합니다. 지역을 삭제하려면 출구·퀘스트 목표·스토리 규칙의 참조부터 제거해야 합니다.

**몬스터 도감** 탭에서는 새 몬스터를 만들고 이름, 체력, 공격력, 경험치와 골드 보상을 편집합니다. 아이템 드롭에 아이템, 확률, 수량을 추가하면 처치 시 각 드롭을 개별 확률로 판정합니다. 따라서 여러 아이템이 한 번에 떨어질 수도 있고, 아무 아이템도 떨어지지 않을 수도 있습니다. 지역 조우나 퀘스트 목표에서 사용 중인 몬스터는 참조가 끊기지 않도록 삭제가 막힙니다. 두 탭의 변경도 `gameplay.json`에 저장됩니다.

몬스터의 강공격은 `heavyAttackDamage`를 0보다 크게 설정해 사용합니다. `heavyAttackEvery`가 3이면 몬스터의 일반 공격 두 번 뒤 강공격을 예고하고, 다음 몬스터 차례에 강공격합니다. `heavyAttackTell`은 예고 문구입니다. 전투 중 `방어`를 입력하면 그 차례의 공격을 받는 대신 몬스터 공격 피해를 줄입니다. 강공격을 방어하면 피해가 25%로, 일반 공격을 방어하면 50%로 감소합니다. 공격 또는 회복 아이템 사용도 몬스터 차례를 발생시키며, 전투에서 `도망`은 즉시 마을로 후퇴합니다.

`아이템·상점` 탭에서 아이템을 추가·삭제하고 종류, 가격, 회복량, 장착 부위, 공격력, 방어력과 최대 내구도를 편집합니다. 월드 맵에서 지역의 `shopItems`를 체크하면 그 지역이 상점이 됩니다. `약제상`, `무기상`처럼 지역을 장터의 출구로 연결해 상점을 구성할 수 있습니다. 게임에서 `목록`, `구매 <아이템>`, `판매 <아이템>`을 사용합니다. 장비는 `장착 <아이템>`과 `해제 무기|방어구`로 바꾸며, 무기의 공격력과 방어구의 방어력이 전투에 적용됩니다. 내구도가 있는 장비는 공격하거나 공격을 받을 때 1씩 닳고, 0이 되면 부서집니다. 상점의 상품·아이템 수치 변경도 `gameplay.json`에 저장됩니다.

**변환 장치·레시피** 탭에서 `stations`와 `recipes`를 편집합니다. 장치마다 표시 이름과 명령어 별칭, 사용 가능 장소, 기본 해금 여부와 안내 문구를 설정할 수 있습니다. 특정 스토리 선택을 완료했을 때 장치를 열려면 스토리 편집기에서 해당 선택지를 선택하고 **스토리 선택 시 해금할 변환 장치**에서 대상을 고릅니다. 이는 선택 효과 `{ "type": "unlockStation", "stationId": "dimensional_rift" }`로 저장됩니다. `{ "type": "discoverRecipe", "recipeId": "ruby_repair" }`로 숨겨진 레시피를 공개할 수도 있으며, `stationUnlocked`와 `recipeKnown` 조건도 지원합니다. 해금된 장치 이름을 입력해 들어간 다음 `레시피`, `넣기 아이템명`, `빼기 아이템명`, `조합`, `나가기`를 사용합니다. 재료는 한 번에 한 개씩 투입하고 `레시피`에서 현재 담긴 재료를 확인합니다. 재료를 넣을 때는 조합하지 않으며, `조합` 명령을 입력해야 결과를 판정합니다. 잘못 넣은 재료는 `빼기 아이템명`으로 돌려놓을 수 있습니다. 조합이 등록되어 있지 않으면 명시적으로 조합을 시도한 시점에 장치 안 재료가 소모됩니다. 확률 결과는 편집기의 가중치 비율로 결정됩니다. 장비 강화는 입력 장비 ID와 다른 결과 아이템 ID를 지정하면 강화 전용 장비만 한 번 변환되게 구성할 수 있고, 장비가 변환될 때 같은 장착 부위의 결과 장비에는 남은 내구도를 이어 줍니다.

월드 맵 편집기의 오디오 선택은 `game/audio-catalog.json` 목록을 사용합니다. 지역별 배경음 ID는 `locations.<지역ID>.ambientAudioId`, 전투 음악과 기본 공격 효과음은 `gameplay.audio`에 저장되고, 몬스터별 공격 효과음은 `monsters.<몬스터ID>.attackSoundId`에 저장됩니다. 새 음원을 추가할 때는 MP3를 `assets/audio/`에 넣고 카탈로그에 고유 ID, 표시 이름, 상대 경로와 유형(`ambience`, `music`, `sfx`)을 등록합니다. 지역 배경음은 지역 이동에 맞춰 재생되고, 전투 음악은 전투 시작·종료에 맞춰 전환됩니다. 공격 효과음은 전투 명령의 공격 발생 시 한 번 재생됩니다.

**Supabase 저장**은 스토리와 게임 데이터를 한 번에 현재 Supabase 프로젝트의 `game_content` 행에 저장합니다. 게임은 로그인 뒤 이 공유 콘텐츠를 먼저 읽으며, 새로고침하면 편집자가 저장한 최신 내용으로 시작합니다. 열린 게임 세션은 자동 변경되지 않으므로 새 버전을 쓰려면 새로고침합니다. 콘텐츠 테이블이 비어 있으면 편집기는 기존 JSON 파일을 최초 등록용 기본값으로 읽습니다. Supabase 저장 기능을 사용하기 전에 `supabase/migrations/202610050001_game_content.sql`을 적용하고, 처음에는 편집기에서 **Supabase 저장**을 눌러 콘텐츠를 등록해야 합니다. 그 전까지 게임은 기본 JSON 파일을 사용하며 안내 문구를 표시합니다.
