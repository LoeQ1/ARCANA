# 아르카나

브라우저에서 플레이하는 명령어 기반 RPG입니다. 플레이어는 지역을 탐험하고, 전투와 퀘스트를 진행하며, 장비·아이템·이야기를 통해 캐릭터를 성장시킵니다. 게임 콘텐츠는 스토리 편집기에서 관리하고 Supabase에 저장할 수 있습니다.

## 주요 기능

- 이메일 로그인과 Supabase 기반 플레이어 기록 저장
- 명령어 입력 방식의 탐험, 이동, 퀘스트, 장비, 상점, 전투
- 선택지와 조건·효과를 연결하는 데이터 기반 스토리
- 몬스터 출현 및 전리품, 지역 탐험 보상 설정
- 턴제 전투와 방어·위험 공격 대응
- 상점 상품과 아이템 능력치 설정
- 지역 및 전투 배경음과 효과음 설정
- 차원 균열 등 변환 장치와 레시피 편집
- 모바일 화면과 가상 키보드 대응

## 플레이 명령어

명령어 목록은 게임 안에서 `도움말`을 입력해 볼 수 있습니다.

| 분류 | 명령어 예시 | 기능 |
| --- | --- | --- |
| 기본 | `보기`, `상태`, `소지품`, `이야기`, `도움말` | 주변·캐릭터·아이템·이야기 확인 |
| 이동 | `이동 숲` 또는 지역 이름 | 다른 지역으로 이동 |
| 탐험 | `탐험` | 지역 탐색, 이벤트 또는 몬스터 조우 |
| 전투 | `공격`, `방어`, `도망`, `사용 회복 물약` | 전투 행동과 아이템 사용 |
| 장비 | `장착 낡은 검`, `해제 무기` | 장비 착용 및 해제 |
| 상점 | `목록`, `구매 회복 물약`, `판매 숲 약초` | 상점 거래 |
| 이야기 | `선택 1` | 현재 장면의 선택지 선택 |

### 변환 장치와 레시피

1. 해금된 장치 이름(예: `차원 균열`)을 입력해 들어갑니다.
2. `레시피`로 알려진 조합과 필요한 재료를 확인합니다.
3. `넣기 <아이템 이름>`으로 재료를 **한 번에 하나씩** 넣습니다. 같은 재료가 여러 개 필요하면 명령을 반복합니다.
4. 재료를 모두 넣은 뒤 `조합`을 입력해 결과를 확정합니다.
5. 조합 전에 재료를 되돌리고 싶으면 `빼기 <아이템 이름>`을 사용하고, `나가기`로 장치를 종료합니다.

재료는 `조합`을 실행할 때 판정됩니다. 레시피가 맞지 않는 경우 넣어 둔 재료가 소모될 수 있으니, 먼저 `레시피`와 현재 투입 목록을 확인하세요. 강화 가능 장비나 무작위 결과 레시피는 편집기에서 정의한 규칙을 따릅니다.

## 스토리 및 콘텐츠 편집

편집기는 이야기뿐 아니라 월드 맵, 몬스터, 아이템, 상점, 탐험 보상, 오디오, 변환 장치와 레시피를 함께 관리합니다. 이야기 장면은 다음 장면과 연결하고, 조건과 효과를 지정해 지역·퀘스트·아이템·전투 진행에 반응하도록 구성합니다.

정적 JSON은 초기 자료 및 Supabase 장애 시 대체 자료입니다. 현재 파일을 새로 만들기만 해서는 엔진이 자동으로 읽지 않습니다. 콘텐츠 구조와 장면 작성 규칙은 [`docs/STORY_AUTHORING.md`](docs/STORY_AUTHORING.md), Supabase 게시 방식은 [`supabase/README.md`](supabase/README.md)에 정리되어 있습니다.

## 프로젝트 구조

```text
index.html                         게임 진입점
editor/index.html                  스토리·게임 콘텐츠 편집기
game/                              게임 엔진과 시스템
content/story/arrival.json         초기 이야기 데이터 및 대체 자료
content/data/gameplay.json         맵·몬스터·아이템 등 초기 데이터 및 대체 자료
audio/                             게임 음악과 효과음 자산
supabase/migrations/               데이터베이스 스키마와 접근 정책
supabase/README.md                 Supabase 설정 및 게시 안내
docs/STORY_AUTHORING.md             이야기·콘텐츠 작성 안내
```

## 배포 시 참고

GitHub Pages에 배포된 게임은 배포된 브랜치/빌드의 파일을 사용합니다. 로컬에서 수정하거나 별도 브랜치에 푸시하는 것만으로 공개 사이트가 바뀌지는 않습니다. Pages가 바라보는 브랜치에 변경을 반영하고 배포가 완료된 뒤 사이트를 새로고침하세요. 콘텐츠를 Supabase에 저장한 경우에도 이미 접속 중인 게임 화면은 새로고침해야 변경 내용을 가져옵니다.
